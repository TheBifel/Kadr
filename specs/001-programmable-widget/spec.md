# 001 — Програмований статичний Android-віджет

Дата: 2026-11-13. Стан: затверджений напрям користувачем; реалізація за цією специфікацією.

## Призначення

Користувач пише HTML-сторінку з CSS і JavaScript. Під час оновлення сторінка сама отримує дані, виконує обчислення й будує довільну композицію. Android-віджет показує статичний знімок до наступного успішного виконання. Vue дозволений; HTML/CSS/JS є єдиним форматом контенту першої версії.

Немає режимів ручного JSON, Markdown, завантаження зображення або UI симуляції ребуту. Зображення, SVG, Canvas та графіки можуть бути частиною самої HTML-сторінки. Ребут, офлайн і помилки перевіряються тестами.

## Сценарії та вимоги

- **FR01** Створити й редагувати кілька незалежних проєктів; кожен містить назву, повний HTML/CSS/JS, тему, заокруглення та політику оновлення. Зберегти їх між запусками.
- **FR02** Редактор показує останній кадр, код і читабельний статус останньої спроби. Зберегти та перебудувати — явна дія. Експортувати/імпортувати сторінку через системний вибір файлів.
- **FR03** Код може використовувати fetch HTTPS із нормальними правилами CORS, inline CSS/JS, SVG/Canvas і локально включений Vue. Файли пристрою, універсальний native bridge та відкриття вікон не надаються.
- **FR04** SDK сторінки: `Kadr.theme`, `Kadr.width`, `Kadr.height`, `Kadr.ready()` і `Kadr.fail(message)`. CSS-токени `--kadr-bg`, `--kadr-fg`, `--kadr-muted`, `--kadr-accent`. Готовність явна; відсутність ready за 15 секунд є помилкою. Перед кадром очікуються шрифти та наявні зображення.
- **FR05** Показувати лише завершений статичний кадр. Після побудови WebView знищується. Немає скролу, постійного JS або анімацій у віджеті. Контент не приймає натискання; native-оболонка має окремі дії.
- **FR06** Час останнього успіху та кнопка ↻ стоять поруч у правому нижньому кутку. Помилка не змінює час успіху. Натискання ↻ ставить одноразове завдання й не потребує відкриття Activity. Натискання кадру відкриває відповідний редактор.
- **FR07** Додати віджет через системний picker або pin request. Прив’язати проєкт до appWidgetId. Дозволені кілька віджетів і різні проєкти; resize перебудовує потрібний розмір.
- **FR08** Інтервали: вручну, 15/30/60/180/360/1440 хв. WorkManager без точних будильників і постійного foreground service. У UI пояснити неточність часу. Опції unmetered network та battery-not-low. Ручний запит не обмежується battery-not-low.
- **FR09** Зберігати конфігурацію та кадри в постійному приватному сховищі. Успішний новий файл кадру записується атомарно до зміни посилання на нього. Збій мережі, JS, ready timeout чи запису не замінює останній успіх. Захист від паралельної побудови одного проєкту та публікації старої версії коду.
- **FR10** Після звичайного reboot і розблокування віджет відновлює збережений кадр, періодичні завдання узгоджуються без дублювання, дані згодом оновлюються. Реєстрація boot і package replaced; WorkManager також відновлює власну БД. Не вимагати ручного відкриття застосунку.
- **FR11** Backup/restore: old/new appWidgetId переприв’язуються; видалення віджета очищує лише binding, а не код проєкту. Force stop документований окремо; до ручного відкриття фонове виконання не гарантується. Direct Boot до першого unlock поза MVP.
- **FR12** Візуальний напрям попереднього мокапа: графіт, лаймовий акцент, світлі/темні картки, українські тексти. Без debug-екрана симуляцій. Системний picker та реальний домашній екран входять у перевірку.

## Межі

Android 12+ (minSdk 31), compile/target 36, перша перевірка API35 x86_64. APK debug для встановлення; Play Store публікація не входить у завдання. Немає сервера Кадру, акаунтів, хмарного рендерингу чи прихованих токенів. Довільна сторінка повинна вкладатися в обмеження кадру; HTML-кнопки в bitmap не інтерактивні. Фоновий розклад неточний за правилами Android. Сумісність OEM не вважається доведеною одним емулятором.

## Критерії приймання

| ID | Доказ |
| --- | --- |
| AC01 | На емуляторі HTML+CSS+async JS змінюють реальний bitmap; Vue-шаблон також рендериться. |
| AC02 | Автотест HTTP fixture: сторінка fetch отримує змінені дані, другий кадр відрізняється. |
| AC03 | Після JS error, fetch failure та timeout hash кадру і lastSuccess незмінні. |
| AC04 | Native-віджет доданий у launcher; час і ↻ видимі поруч; tap ↻ оновлює кадр у фоні без Activity. |
| AC05 | Код, тема, радіус та інтервал зберігаються після перевідкриття; різні проєкти не перезаписуються. |
| AC06 | Періодичне WorkManager-завдання існує; примусовий запуск OS job перевіряє той самий шлях. |
| AC07 | Реальний adb reboot: після boot/unlock збережений кадр є, binding не загублений, job перепланований; ручне відкриття Activity не використане для відновлення. |
| AC08 | Resize і два віджети не ламають прив’язки; restore remap має автоматизовану перевірку. |
| AC09 | Debug APK зібраний, unit/instrumentation перевірки пройшли; скріншоти редактора й домашнього екрана збережені та показані користувачу під час роботи. |
